# Hợp đồng F01 và phần đề xuất triển khai

Căn cứ: tài liệu nhóm “Chốt dữ liệu chung và API F01, F03”, ngày 06/11/2026,
và issue #8. Bảo 04 làm F01; Hân gọi từ S01; Nhật review; Bảo 06 nhập dữ liệu SQLite.

## Những nội dung đã chốt

```http
GET /api/v1/places/recommendations?interests=nature&interests=coffee
Authorization: Bearer <access_token>
```

- Dùng query `interests` lặp cho nhiều lựa chọn, không dùng chuỗi phân cách dấu phẩy.
- Mã sở thích: `nature`, `coffee`, `culture`, `food`.
- Xét địa điểm khớp ít nhất một sở thích; ưu tiên khớp nhiều sở thích hơn.
- Tối đa 3 kết quả. Có 1–2 kết quả thì trả đúng số đang có.
- Tên trường mỗi kết quả: `place_id`, `name`, `image_url`, `reason`.
- `image_url: null` để Hân dùng ảnh mặc định.
- Không có kết quả: HTTP 200, `{"places": []}`.
- Thiếu/mã sở thích sai: HTTP 422, `code: VALIDATION_ERROR`, `field: interests`.
- Gửi Bearer token theo hợp đồng tài khoản.

Ví dụ phản hồi hiện có khi chọn `coffee`:

```json
{
  "places": [
    {
      "place_id": "P006",
      "name": "Là Việt Coffee — Nguyễn Công Trứ",
      "image_url": null,
      "reason": "Phù hợp với sở thích cà phê của bạn."
    },
    {
      "place_id": "P010",
      "name": "Still Cafe",
      "image_url": null,
      "reason": "Phù hợp với sở thích cà phê của bạn."
    },
    {
      "place_id": "P011",
      "name": "An Cafe",
      "image_url": null,
      "reason": "Phù hợp với sở thích cà phê của bạn."
    }
  ]
}
```

Ví dụ lỗi:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Chọn ít nhất một sở thích hợp lệ: nature, coffee, culture, food.",
  "field": "interests"
}
```

## Cách triển khai của bản này

`backend/main.py` gắn router trong `places_api.py`. Catalog đọc JSON từ đường dẫn
tuyệt đối tính theo module, không phụ thuộc thư mục làm việc của dữ liệu.
Khởi động backend theo README từ `backend/`.

- Sở thích lặp được tính một lần. Khi bằng điểm, sắp `place_id` tăng dần để kết quả ổn định.
  Cách xử lý hòa điểm là **đề xuất triển khai**, không phải quyết định đã chốt của nhóm.
- F01 mặc định không dùng bản ghi `MOCK`. Bản ghi có tên/nhãn có nguồn nhưng lịch tuần
  chưa đủ vẫn có thể được gợi ý; F01 không xác nhận tính khả thi của một lịch trình.
  F02/F05 phải xét dữ liệu lịch và chất lượng từng trường riêng.
- Lý do được tạo từ các nhãn sở thích khớp. Bản F01 này không gọi AI hoặc API bên ngoài
  trong mỗi request. Phần AI PLAN/ADAPT thuộc Nhật.
- Catalog được cache trong tiến trình; khởi động lại backend sau khi sửa JSON.

## Ghép với tài khoản của Đăng

Ngày kiểm tra 07/11/2026, tài khoản ở PR #12 chưa vào `main`.
`places_api.authenticate` gọi `auth.session_response(credentials)` đúng giao diện của PR đó.

- Thiếu Bearer: HTTP 401, `AUTH_REQUIRED`.
- Module tài khoản chưa có: HTTP 503, `AUTH_NOT_READY`. Đây là trạng thái ghép tạm của bản này.
- Khi có module tài khoản: chuyển nguyên lỗi session từ module đó, gồm token sai,
  hết hạn, đã đăng xuất. Không chấp nhận token chỉ vì chuỗi có tiền tố Bearer.

Khi ghép PR #12, giữ cả lifespan khởi tạo tài khoản của Đăng và hai dòng của F01:

```python
from places_api import router as places_router

app.include_router(places_router)
```

Không thay thế `auth.py` bằng mock; không đưa dependency override của test vào app.
Script `backend/scripts/check_f01_auth.py` kiểm tra code auth thật trên SQLite tạm.

Trong lúc PR #12 còn mở, có thể chạy hai module cùng nhau mà không merge PR đó:

```bash
backend/.venv/bin/python -m pip install -r backend/requirements-integration.txt
backend/.venv/bin/python backend/scripts/check_f01_auth.py --auth-ref origin/feat/2-auth-api
backend/.venv/bin/python backend/scripts/run_f01_demo.py --port 8001
```

Harness đọc code từ Git ref của **repo nhóm đã tin cậy**, ghim SHA lúc khởi động và
in SHA ra Terminal; không tải/chạy ref từ nguồn ngoài. Mặc định dùng SQLite tạm,
xóa tài khoản demo khi dừng. Đây là công cụ tích hợp cục bộ, không thay thế cách ghép
router/lifespan trên main. Hướng dẫn thao tác Swagger trong `docs/F01-HUONG-DAN-BAO04.md`.

## Hàm gọi cho S01

`mobile/src/services/places.ts` xuất `fetchRecommendations`, `Interest` và
`RecommendationsError`. Hàm nhận `apiUrl` là địa chỉ gốc HTTP(S), `accessToken`,
`interests` và `signal` tùy chọn; trả nguyên `{places}`. Query lặp được dựng sẵn;
lỗi server giữ `status`, `code`, `field`; lỗi mạng dùng `NETWORK_ERROR`.
Lỗi hủy request được chuyển tiếp để màn hình bỏ qua request cũ.

Hân vẫn cần gắn vào state/màn hình: lấy token từ luồng đăng nhập, loading/error/empty,
ảnh mặc định và hủy/bỏ qua kết quả request cũ khi đổi sở thích. Hàm này chưa được
ghép S01/Android. Các test transport chạy bằng `cd mobile && npm run test:f01`
(Node hỗ trợ strip TypeScript, dùng Node >=22.18).

## Chi tiết dữ liệu còn là đề xuất để Leader chốt

Tên trường `places` và `travel_times` theo đúng tài liệu nhóm.
Các enum/shape dưới đây là **v0.1 đề xuất**, vì mục 9 của tài liệu chưa khóa chúng:

| Nội dung | Đề xuất |
|---|---|
| `area` | `DALAT_CENTER`, `TUYEN_LAM`, `LOC_AN`, `DI_LINH`, `BAO_LOC`; là vùng sắp tuyến, không phải mã hành chính |
| `environment` | `INDOOR`, `OUTDOOR`, `MIXED`, `UNKNOWN` |
| `data_status` | `SOURCED`, `MOCK`, `UNVERIFIED` |
| `opening_hours` | `timezone` và `weekly` gồm `mon`…`sun`; mỗi ngày là các khoảng `{start,end}` |
| Chưa biết giờ | `null` ở ngày đó; không được xem là mở cả ngày |
| Đã biết đóng cửa | `[]` ở ngày đó |
| Thiếu thời lượng | `visit_duration_minutes: null`, bản ghi giữ `UNVERIFIED` |
| `travel_time_id` khi bàn giao | `null`, backend sinh khi nhập SQLite |

Ví dụ **MOCK**, không phải giờ của địa điểm thật:

```json
{
  "timezone": "Asia/Ho_Chi_Minh",
  "weekly": {
    "mon": [],
    "tue": [{"start": "08:00", "end": "12:00"}, {"start": "13:30", "end": "17:00"}],
    "wed": null,
    "thu": null,
    "fri": null,
    "sat": null,
    "sun": null
  }
}
```

`SOURCED` chỉ dùng sau đối chiếu các trường cần thiết. Với chặng di chuyển, đây vẫn
là **ước tính từ nguồn/thuật toán**, không phải thời gian thực hoặc đo thực địa.
Chi tiết từng địa điểm nằm trong `backend/data/data_review.json`.
